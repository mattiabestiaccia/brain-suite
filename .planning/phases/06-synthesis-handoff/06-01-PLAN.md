Replace the 12-line stub with a complete agent spec. Follow the non-conversational agent pattern established by brain-researcher.md (role, execution flow, output format, constraints) but adapted for document generation rather than data fetching.

**YAML frontmatter:**
- name: brain-synthesizer
- description: Generates cross-dimensional analysis, narrative synthesis, and GSD-ready handoff documents
- tools: Read, Write, Bash, Glob

**Structure the spec with these sections:**

1. **Role:** Non-conversational document generator. Single agent with 3 modes. Does NOT interact with the user. Reads artifacts, produces documents, shows result summary.

2. **Input Loading (shared across all modes):**
   - Read .brainstorm/IDEA.md for idea context
   - Read .brainstorm/SESSION.md for session state and dimension inventory
   - Glob .brainstorm/dimensions/*.md and Read ALL found dimension files
   - For synthesize mode: also Read .brainstorm/ANALYSIS.md
   - For handoff mode: Read .brainstorm/SYNTHESIS.md if exists, else .brainstorm/ANALYSIS.md if exists
   - Detect thin content: sections with only placeholder questions (from Phase 3 pattern where undiscussed sections get spunti questions) — these are NOT substantive content

3. **Analyze Mode — produce ANALYSIS.md:**
   - Organized by emergent themes, NOT by dimension pairs or predefined categories
   - A theme = a pattern, tension, synergy, contradiction, or opportunity spanning 2+ dimensions
   - For each theme: concise name, which dimensions contribute, description of the pattern, type classification (synergy | tension | contradiction | opportunity | gap), implications for the idea
   - Internal structure within each theme at agent's discretion (per user decision)
   - After themes: Gap Analysis section with:
     - Unexplored dimensions (from SESSION.md)
     - For explored dimensions: list specific sections with only placeholder content (rigorous gap signaling per user decision)
     - Overall analysis confidence rating based on coverage
   - Footer: `*Generated by /brain:analyze on YYYY-MM-DD*`

4. **Synthesize Mode — produce SYNTHESIS.md:**
   - Narrative, discursive document — tells the story of the idea seen from all angles
   - Audience: non-technical stakeholders (client, co-founder, investor)
   - Cohesive vision, NOT a list of recommendations, NOT a summary, NOT a report
   - Anti-patterns to enforce in the prompt: "This is not a bullet-point summary. This is not a structured report. Tell the story of this idea as a cohesive narrative — one continuous argument that weaves together insights from all explored dimensions."
   - Length adapts to richness of content (agent decides)
   - Gap signaling: brief note at the end about missing dimensions (less detailed than analysis)
   - Footer: `*Generated by /brain:synthesize on YYYY-MM-DD*`

5. **Handoff Mode — produce HANDOFF.md:**
   - 6 REQUIRED sections always present (## headings):
     - Product Vision — source: IDEA.md + product dimension. Maps to GSD "What This Is" + "Core Value"
     - Problem & Opportunity — source: product + market dimensions. Maps to GSD "Context"
     - Target Users — source: users dimension. Maps to GSD personas/requirements scoping
     - Technical Constraints — source: tech dimension. Maps to GSD "Constraints"
     - Competitive Edge — source: competitors dimension. Maps to GSD differentiation
     - Revenue Model — source: business dimension. Maps to GSD business model context
   - Additional sections allowed if content warrants (agent decides)
   - DECLARATIVE language: "The product is X", "Users are Y" — NOT "We explored X", "The user mentioned Y"
   - Opinionated: where brainstorming produced a clear direction, declare it as a decision. Where ambiguity remains, flag explicitly with a "Decision needed:" prefix
   - No indication of source level (synthesis vs dimensions only) — document stands alone
   - Gap signaling: same as synthesis (note about missing dimensions)
   - Footer: `*Generated by /brain:handoff on YYYY-MM-DD*`

6. **Output Summary (shared pattern):** After writing the document, display a brief summary to the user:
   - For analyze: number of themes found, theme names listed, gap analysis highlights
   - For synthesize: document length, key narrative arc, gaps noted
   - For handoff: all 6 section headings with one-line summary each, plus any additional sections

7. **Constraints:**
   - Maximum Read context: load ALL dimension files but do NOT load session logs (.brainstorm/sessions/) — too noisy
   - Do NOT interact with the user during generation
   - Do NOT ask questions or request clarification — work with what's available
   - If a dimension has only thin/placeholder content, note it in gaps but still extract what signal exists
   - Do NOT use Exa MCP or any web tools — pure analysis from existing artifacts
