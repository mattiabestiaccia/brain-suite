Replace the 7-line stub with a complete markdown-as-prompt command file (~280-320 lines). Follow the EXACT same architectural pattern as `commands/brain/new.md` (299 lines, Phase 2 output).

**Structure the file in these sections:**

1. **Header** (~5 lines): Command name, usage, $ARGUMENTS capture for dimension name.

2. **Setup** (~40 lines):
   - Resolve paths via Bash: `BRAIN_REF=$(echo $HOME/.claude/brain-suite/references)`, `BRAIN_TPL=$(echo $HOME/.claude/brain-suite/templates)`
   - Validate dimension from $ARGUMENTS (first word, lowercase). Valid: product, tech, market, business, competitors, users. If invalid/missing: list valid options and stop.
   - Load context (all via Read tool with resolved paths):
     - `.brainstorm/IDEA.md` (REQUIRED -- fail if missing, tell user to run `/brain:new` first)
     - `.brainstorm/SESSION.md` (REQUIRED)
     - `$BRAIN_TPL/<dimension>.md` (target template for section tracking)
     - `$BRAIN_REF/questioning.md` (for mode behavior details)
   - Use Glob to find `.brainstorm/dimensions/*.md` and Read ALL existing dimension files (cross-dimensional context)
   - Create directories: `mkdir -p .brainstorm/dimensions .brainstorm/sessions`
   - Check if `dimensions/<dimension>.md` already exists: if yes, note to user "You've already explored [dimension]. This session will replace the previous exploration." (Phase 4 adds deepen/fresh choice -- for now, warn and overwrite)

3. **Opening** (~20 lines):
   - Per user decision: open with a riepilogo of what IDEA.md says about this dimension (2-3 sentences MAX, not a monologue -- respect the 8-line rule)
   - Announce default mode briefly per brain-explorer agent's per-dimension defaults table: "Per [dimension] partiamo in modalita [mode] -- ci stai?" (per user decision: brief mention, not a formal menu)
   - Ask first targeted question based on IDEA.md seeds relevant to this dimension

4. **Conversation Flow** (~60 lines):
   - Voice-first patterns (replicate from new.md): summary-then-question, 8-line max, one question rule, expand short answers, casual tone, no filler praise, tolerance for informal input
   - Self-check before every response (under 8 lines? exactly one question? adding value?)
   - Template section coverage tracking: INVISIBLE like Phase 2 coverage tracking. Internally note which template sections have been touched with substantive content. Do NOT name template sections directly. Do NOT use checklist language.
   - Hybrid flow per user decision: free conversation initially (several exchanges), then naturally guide toward uncovered template sections. Transition must feel organic: "There's one angle we haven't hit yet -- [topic in conversational language]." NEVER say "Let's cover the Problem Statement section."
   - Mode behavior: follow the default mode from the per-dimension table. Mode switching is micro-interventions (2-3 exchanges in alternate mode, then return to default). Frame switches as suggestions: "Stai dando molto per scontato -- vuoi che faccia il challenger per un momento?" User decides.
   - Assumption challenging: per brain-explorer spec -- spot implicit assumptions, challenge constructively, one at a time, give credit when it holds up.

5. **Cross-Dimensional Awareness** (~25 lines):
   - Per user decision: connections and contradictions emerge REACTIVELY during conversation (not forced)
   - When a contradiction is identified: signal it, annotate it, suggest resolution or which dimension to revisit
   - Cross-dimensional notes appear both inline (where they emerge in the conversation) AND collected in a dedicated "Cross-Dimensional Notes" section at end of dimension document
   - Per user decision: do NOT force connections. Only surface them when natural in the conversation flow.

6. **Depth Gating** (~15 lines):
   - Per user decision: hybrid -- explorer suggests when key template sections are covered, user decides to continue or stop
   - When all key sections have substantive content: "We've hit the main angles. Want to go deeper anywhere, or wrap up?"
   - If user wants to continue: keep exploring, push for depth on areas of interest
   - If user wants to stop: proceed to Session Closure
   - If critical sections remain untouched: "Before we wrap -- we haven't touched on [topic]. Worth a quick look?"

7. **Session Closure** (~40 lines):
   - Per user decision: show riepilogo finale and ask "Va bene cosi o vuoi aggiustare qualcosa?"
   - Handle corrections: update the dimension document content (NOT the session log -- per user decision, session log stays faithful to original conversation)
   - Generate artifacts (see sections below)
   - Update SESSION.md
   - After saving: suggest which dimension to explore next (read dimensions-guide.md at this point, same pattern as new.md delayed loading). Suggestion must reference conversation content, not be generic.

8. **Artifact: dimensions/<dimension>.md** (~30 lines):
   - Use Write tool to create `.brainstorm/dimensions/<dimension>.md`
   - Follow the FULL template structure (all sections present -- per user decision)
   - Discussed sections: populated with distilled content from conversation. Standalone prose (not Q&A, no "you mentioned", no conversation artifacts)
   - Undiscussed sections: 1-2 placeholder questions from the template as spunti (per user decision: useful questions, not empty markers)
   - Add "## Cross-Dimensional Notes" section at the end with all connections/contradictions that emerged
   - Footer: `*Explored via /brain:explore <dimension> on YYYY-MM-DD*`
   - Per user decision: do NOT track mode used in the dimension document. Content matters, not process.

9. **Artifact: sessions/<dimension>-<date>.md** (~25 lines):
   - Use Write tool to create `.brainstorm/sessions/<dimension>-YYYY-MM-DD-HHMM.md` (use time component to prevent same-day collision per research recommendation)
   - Get current datetime via Bash: `date +%Y-%m-%d-%H%M`
   - Distilled Q&A format: remove greetings, filler, repetitions, meta-conversation. Keep ALL substantive content.
   - Merge related exchanges: if a topic spans multiple back-and-forths, synthesize into one Q&A pair
   - Header with dimension name, date, approximate exchange count
   - Key Themes section (3-5 bullets)
   - Per user decision: corrections from recap go to dimension file only, NOT to session log

10. **SESSION.md Update** (~15 lines):
    - Read current SESSION.md
    - Update the dimension's Status to "explored", Date to today, Notes with 1-2 word summary
    - Update "Last updated" date
    - Add entry to Session Notes with key insights
    - Write updated SESSION.md

11. **Behavioral Reinforcement** (~20 lines):
    - Same pattern as new.md: restate critical rules at end of file for LLM recency bias
    - ALWAYS: one question, under 8 lines, add value, casual tone, follow user energy, invisible tracking
    - NEVER: reveal tracking, multiple questions, monologues, filler praise, formal tone, questionnaire mode, correct grammar, name template sections

**Critical patterns to replicate from new.md:**
- Runtime reference loading via Bash `echo $HOME` then Read tool (NOT @ references)
- Invisible coverage/section tracking (observational, never revealed)
- Recap-confirm-save flow
- Behavioral reinforcement at file end
- Self-check protocol before every response

**What to avoid and WHY:**
- Do NOT use Task tool to spawn brain-explorer agent (breaks multi-turn conversation -- validated in Phase 2)
- Do NOT duplicate the full reference file content inline (context budget -- reference the behavioral patterns, load questioning.md for mode details)
- Do NOT load voice-interaction.md at startup (explore.md embeds the critical rules directly, same as new.md does)
- Do NOT create a checklist-style exploration flow (per user decision: free conversation first, structured coverage emerges naturally)
- Do NOT track mode in dimension artifacts (per user decision: "conta il contenuto, non il processo")
