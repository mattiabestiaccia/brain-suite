  <action>
Replace the stub with a complete markdown-as-prompt command file implementing the intelligent hub pattern.

Structure the command in these sections:

**Header:** `/brain:resume` -- Resume a previous brainstorming session. Loads full context and acts as an intelligent hub.

**Setup:**
1. Resolve reference path: `BRAIN_REF=$(echo $HOME/.claude/brain-suite/references)`
2. Read `.brainstorm/IDEA.md` -- REQUIRED. If missing, tell user: "Non c'e ancora un'idea. Lancia `/brain:new` per iniziare." and STOP.
3. Read `.brainstorm/SESSION.md` -- REQUIRED. If missing, tell user to run `/brain:new` first and STOP.
4. Use Glob to find `.brainstorm/dimensions/*.md` and read ALL existing dimension files. These provide the full exploration context.
5. Read `$BRAIN_REF/dimensions-guide.md` -- for relationship-based next-dimension suggestion.

**Narrative Summary (different tone from /brain:status -- per locked decision):**

The summary is conversational, not tabular. It should feel like a collaborator catching you up.

- When 1+ dimensions explored:
  - Brief idea reminder (1 sentence)
  - What has been explored: narrative form, ONE key insight per explored dimension (not a comprehensive summary)
  - What remains unexplored
  - Suggest the next dimension to explore with a reason tied to conversation content
  - Keep it under 10 lines total. This is a conversation opener, not a report.
  - Tone example: "Stavi lavorando su **[idea]**. Hai esplorato [N] dimensioni finora: da **[dim1]** e emerso che [insight], da **[dim2]** [insight]. Mancano ancora: [remaining]. Ti suggerisco **[next]** perche [reason]. Partiamo?"

- When 0 dimensions explored (edge case):
  - "Hai un'idea registrata -- **[title]** -- ma non hai ancora esplorato nessuna dimensione."
  - Suggest a first dimension based on dimensions-guide.md (typically product or the most natural starting point).
  - "Vuoi partire con **[suggested]**?"

**User Response Handling (intelligent hub -- per locked decision):**

After presenting the summary, LISTEN to the user's response and act accordingly. Do NOT bounce to other commands. Handle everything internally:

- **User accepts proposal** (e.g., "si", "ok", "partiamo", "va bene"):
  - Resolve explore.md path via Bash `echo $HOME/.claude/commands/brain/explore.md`
  - Read explore.md via Read tool
  - Execute the exploration flow with the proposed dimension pre-set
  - This is the same delegation pattern used by shortcut commands (product.md, tech.md, etc.)

- **User names a different dimension** (e.g., "no, voglio fare competitors", "partiamo da tech"):
  - Same delegation to explore.md, but with the user's chosen dimension

- **User asks for status** (e.g., "fammi vedere lo status", "a che punto siamo"):
  - Display status inline using the same format as /brain:status (idea title, progress bar, dimension grid)
  - Do NOT redirect to `/brain:status`. Handle it here.
  - After displaying, re-propose the next dimension

- **User asks to review a dimension** (e.g., "fammi vedere cosa avevo scritto su product"):
  - Load and display the relevant dimension file content
  - After review, ask what they want to do next

- **User wants to add a custom dimension** (e.g., "voglio aggiungere una dimensione"):
  - Suggest using `/brain:add-dimension` for this (it's a separate workflow with slug generation and template creation that is better handled by its dedicated command)

- **Other intents**: respond conversationally and guide toward next action

**Behavioral reinforcement (at end of file, for LLM recency bias):**
- You are a collaborator catching someone up, not a system loading a save file
- Keep the narrative summary under 10 lines
- ONE key insight per explored dimension, not comprehensive summaries
- After the summary, listen and act on the user's intent
- Handle status display, dimension review, and explore launch internally
- Only suggest /brain:add-dimension for custom dimensions (it has specific slug/template logic)
