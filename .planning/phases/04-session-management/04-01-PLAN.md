<task type="auto">
  <name>Task 2: Create /brain:add-dimension command file</name>
  <files>commands/brain/add-dimension.md</files>
  <action>
Replace the stub with a complete markdown-as-prompt command file implementing custom dimension creation.

Structure the command in these sections:

**Header:** `/brain:add-dimension` -- Add a custom dimension to explore beyond the 6 built-ins.

**Setup:**
1. Read `.brainstorm/SESSION.md` -- REQUIRED. If missing, tell user to run `/brain:new` first and STOP.

**Interaction flow:**
1. Check `$ARGUMENTS` for dimension name. If empty, ask the user for a dimension name.
2. Ask for a brief description (1-2 sentences) of what they want to explore in this dimension.
3. Generate a slug from the dimension name:
   - Use bash: `echo "$DIMENSION_NAME" | iconv -f utf-8 -t ascii//TRANSLIT 2>/dev/null || echo "$DIMENSION_NAME" | tr '[:upper:]' '[:lower:]' | tr ' ' '-' | tr -cd 'a-z0-9-' | sed 's/--*/-/g' | sed 's/^-//;s/-$//'`
   - Fallback if iconv fails: simple tr pipeline (lowercase, spaces to hyphens, strip special chars)
4. Check if the slug already exists in SESSION.md dimension table. If yes, tell user this dimension already exists and STOP.
5. Create the freeform template file at `.brainstorm/templates/<slug>.md`:
   - mkdir -p .brainstorm/templates
   - Template structure (freeform, NOT rigid like built-in templates per locked decision):
     ```
     # [Dimension Name]
     > Template for .brainstorm/dimensions/[slug].md
     > Explorer uses these sections as conversation anchors during exploration.

     ## Overview
     [User's description]. What are the key aspects to explore?

     ## Key Considerations
     What factors are most important? What constraints or opportunities exist?

     ## Connections to Other Dimensions
     How does this dimension relate to and influence the other dimensions of the idea?

     ## Open Questions
     What needs further investigation or validation?
     ```
6. Append a new row to SESSION.md's Explored Dimensions table:
   `| [slug] | not started | - | - | custom |`
7. Confirm to user: "Dimensione **[name]** aggiunta. Puoi esplorarla con `/brain:explore [slug]`."

**Important constraints:**
- Custom dimensions do NOT get shortcut commands (locked decision -- shortcuts reserved for 6 built-ins).
- Custom templates are freeform (few generic headings, not 5-6 specific sections like built-in templates).
- Template goes in `.brainstorm/templates/` (NOT in the installed reference templates directory -- that's a symlink to the repo).
- Multiple words allowed in name, any language.
- Flexible naming with automatic slug for file paths.
  </action>

  </verify>
