  <action>
Replace the current stub with a comprehensive command prompt file. The file IS the prompt — Claude reads it when user invokes `/brain:new` and follows the instructions for the entire multi-turn conversation.

**File structure (in this order):**

1. **Header + description** — `# /brain:new` with one-line description

2. **Setup section** — Instructions to load reference files at conversation start:
   - Resolve path via Bash: `BRAIN_REF=$(echo $HOME/.claude/brain-suite/references)` — use the resolved absolute path for all Read calls (tilde may not expand in Read tool)
   - Read `$BRAIN_REF/voice-interaction.md` — voice and interaction patterns (MUST follow throughout)
   - Read `$BRAIN_REF/questioning.md` — only the Socratic mode section (not full file, save context)
   - Do NOT read dimensions-guide.md at startup — load it later at closure time for dimension suggestion

3. **Existing session check** — Before conversation:
   - Use Glob to check if `.brainstorm/IDEA.md` exists
   - If exists: ask user "start fresh or continue with existing idea?"
   - Start fresh: create `.brainstorm/archive/<ISO-date-with-dashes>/` via Bash mkdir, then `mv` IDEA.md, SESSION.md, and if they exist: dimensions/, sessions/, SYNTHESIS.md, HANDOFF.md to archive. Then proceed with new session.
   - Continue: tell user to use `/brain:resume` instead. End command.
   - If no .brainstorm/ exists: create it via `mkdir -p .brainstorm` and proceed

4. **Opening** — Open canvas start:
   - Single open question, casual tone, inviting the user to describe their idea
   - Example mood (not verbatim): "So, what's the idea?" or "Tell me about what you're thinking of building"
   - Do NOT mention coverage tracking, dimensions, or methodology

5. **Conversation flow rules** — The behavioral core:
   - Follow ALL patterns from voice-interaction.md (loaded in setup)
   - Summary-then-question pattern: brief recap (2-3 sentences) + exactly one question
   - Target response length: 3-5 sentences before the question, max 8 lines
   - One question rule: NEVER ask two questions. Pick the more important one.
   - Expand short answers: interpret, add depth, suggest implications. Never just acknowledge.
   - Tolerance for informal input: never correct grammar, extract meaning from messy voice-to-text
   - Follow the user's energy and topic — if they spontaneously enter dimensional territory (competitors, tech, market), follow naturally. Do NOT redirect to a "structure"
   - This is brainstorming, not an interview

6. **Internal coverage tracking** — CRITICAL: invisible to user:
   - Track 3 core points: (1) Problem/need, (2) Target audience, (3) Rough solution/approach
   - Frame as observational: "note when these emerge" not "steer toward them"
   - User may cover these spontaneously without being asked directly
   - When all 3 are roughly understood, MAY propose saving — but only if user seems to be winding down. If they're actively brainstorming, let them continue
   - NEVER reveal the tracking. Never say "We've covered the problem, let's move to audience." Never use checklist language.
   - Self-check instruction: "Before each response, verify: (1) Is it under 8 lines before the question? (2) Is there exactly one question? (3) Am I adding value, not just parroting?"

7. **Idea evolution tracking** — Light touch:
   - If the idea mutates significantly during conversation, note both starting point and current direction
   - If divergence is obvious, signal it lightly (brief note, not formal intervention)
   - Example: "Interesting — you started with X but now you're really describing Y. Both are valid, but they're different ideas. Which direction feels right?"
   - If divergence is subtle, don't force it

8. **Session closure** — Recap-confirm-save-suggest flow:
   - When proposing to save (coverage reached + user winding down, OR user explicitly says they're done):
     a. Show structured recap of key points understood (the idea, the problem, who it's for, the approach — but only what was actually discussed)
     b. User reviews: confirms, corrects, or adds
     c. If corrections: incorporate and show updated recap
     d. On confirmation: generate and save artifacts (see artifact generation below)
   - After saving: Read dimensions-guide.md via Read tool, then suggest which dimension to explore first based on what emerged in conversation. The suggestion should feel natural: "You were already talking about competitors, maybe start there" — not a generic "start with product"

9. **Artifact generation — IDEA.md**:
   - Write to `.brainstorm/IDEA.md` via Write tool
   - Emergent structure: sections reflect what came out of conversation, NOT a fixed template
   - Start with `# [Idea Name]` and one-sentence elevator pitch as blockquote
   - Sections for each topic that was substantially discussed (e.g., "## The Problem", "## Who It's For", "## The Approach")
   - If a topic was barely touched, it gets a brief mention in a "Seeds" or "Open Questions" section, not a full section
   - "## How the Idea Evolved" section ONLY if the idea actually mutated during conversation. Omit entirely if stable.
   - "## Emerging Threads" section for dimensional hints that came up naturally (competitors mentioned, tech constraints flagged, etc.) — seeds for future exploration
   - Distilled writing: clean, concise, substance only. No conversational noise. Write as if someone who was NOT in the conversation needs to understand the idea.
   - Each section reads as standalone paragraph, not Q&A pair. No "you mentioned", "we discussed", "as you said".
   - Footer: `---\n*Generated by /brain:new on <date>*\n*Source: interactive brainstorming session*`

10. **Artifact generation — SESSION.md**:
    - Write to `.brainstorm/SESSION.md` via Write tool
    - Structure:
      ```
      # Brainstorming Session

      **Idea:** [one-line summary]
      **Started:** <date>
      **Last updated:** <date>
      **Status:** initial-brainstorm

      ## Explored Dimensions

      | Dimension | Status | Date | Notes |
      |-----------|--------|------|-------|
      | product | not started | - | - |
      | tech | not started | - | - |
      | market | not started | - | - |
      | business | not started | - | - |
      | competitors | not started | - | - |
      | users | not started | - | - |

      ## Session Notes

      - Initial brainstorming session via /brain:new
      - [Key observations from the conversation]
      - Suggested next: [dimension] (based on conversation content)

      ## Idea Evolution

      [Only if the idea changed — brief note. Otherwise: "Idea remained stable during initial session."]
      ```
    - This file must be readable by Phase 3 (/brain:explore) and Phase 4 (/brain:resume, /brain:status)

11. **Behavioral reinforcement (at end of file, for recency bias)**:
    - Restate critical rules in imperative form:
    - "ALWAYS: one question per response. NEVER two."
    - "ALWAYS: under 8 lines before the question."
    - "NEVER: reveal coverage tracking. NEVER: checklist language."
    - "NEVER: questionnaire mode. This is brainstorming."
    - "ALWAYS: expand short answers. Never just acknowledge."

**What to AVOID and why:**
- Do NOT use `@` file references in the command (symlinked file can't contain hardcoded absolute paths — use Read tool with resolved $HOME path instead)
- Do NOT include the full content of reference files inline (wastes context window — load at runtime)
- Do NOT create a rigid template for IDEA.md (CONTEXT.md locked: emergent structure)
- Do NOT spawn brain-explorer agent (CONTEXT.md locked: direct command for Phase 2)
- Do NOT implement `/brain:resume` logic (deferred to Phase 4 — just redirect user to the command)
