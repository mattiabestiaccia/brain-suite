  <action>
    Create `references/` directory and author 4 reference files. These are the "brain" of the tool — they define the brainstorming methodology that brain-explorer will use. Content must be **opinionated and actionable**, not generic documentation.

    **references/voice-interaction.md** — Voice-first interaction patterns for the brain-explorer agent.
    Must cover (per CONTEXT.md locked decisions):
    - Explorer voice: thinking partner — casual but sharp, like brainstorming with a co-founder. Direct, occasionally challenges, never patronizing.
    - Responses short and scannable (aim for 3-5 sentences max before the question).
    - Exactly one question per response (never stack questions).
    - Summary before question pattern: brief recap of what was discussed, then the next question.
    - Tolerance for informal spoken input — never correct grammar, never ask for clarification on phrasing. Extract the meaning.
    - When user gives a short answer, expand it thoughtfully, then ask the next question. Don't just acknowledge and move on.
    - Anti-patterns to avoid: long monologues, multiple questions, formal/corporate tone, "that's a great point" filler.

    **references/questioning.md** — Questioning methodology covering the three modes.
    Must cover (per CONTEXT.md locked decisions):
    - **Socratic mode** (default): Guided discovery through questions. Build on user's answers. Lead them to uncover their own assumptions. Don't tell — ask.
    - **Challenger mode** (for market/competitors dimensions): Devil's advocate. Actively challenge assertions with "but what if..." and "how do you know...". Push back on optimistic claims. Surface risks the user hasn't considered.
    - **Creative/divergent mode** (for product dimension): Expansive thinking. "What if there were no constraints?", "What's the opposite of what you're doing?", analogies from other industries, brainstorm wild ideas before converging.
    - Per-dimension default mode mapping: product → creative, tech → socratic, market → challenger, business → socratic, competitors → challenger, users → socratic.
    - How to transition between modes within a session (user can request mode change).
    - Depth gating: when key points are covered, suggest moving on but let user decide. Signals to watch for: circular answers, user saying "I think that's enough", coverage of all template sections.

    **references/frameworks.md** — Startup-oriented analytical frameworks.
    Must cover (per CONTEXT.md locked decisions):
    - **Lean Canvas**: Problem, Solution, Key Metrics, Unique Value Proposition, Unfair Advantage, Channels, Customer Segments, Cost Structure, Revenue Streams. Include brief explanation of each block with example prompts the explorer can use.
    - **Jobs To Be Done (JTBD)**: Job statement format ("When I [situation], I want to [motivation], so I can [expected outcome]"). Functional, emotional, social jobs. Competing solutions (current alternatives).
    - **Value Proposition Canvas**: Customer Profile (jobs, pains, gains) vs Value Map (products/services, pain relievers, gain creators). How to use it during exploration.
    - How the explorer should weave these frameworks into conversation naturally — NOT as forms to fill, but as lenses to apply when relevant. Framework should emerge from conversation, not be imposed.

    **references/dimensions-guide.md** — Guide to the 6 built-in dimensions.
    Must cover:
    - Overview of the 6 dimensions: product, tech, market, business, competitors, users.
    - For each dimension: purpose (what you're trying to understand), key questions (5-7 starter questions), default exploration mode, what a good output looks like, common pitfalls.
    - How dimensions relate to each other (cross-references, dependencies — e.g., "tech choices constrain product features", "market size affects business model viability").
    - Suggested exploration order for new ideas (product → users → market → competitors → business → tech) with explanation of why, but emphasize non-linear exploration is fine.
    - When to revisit a dimension (signals from other dimensions that invalidate earlier assumptions).

    Each file should be 60-150 lines. Content must be specific enough that a Claude agent reading it can immediately adopt the described behavior.
  </action>

  <action>
    Create `templates/` directory and author 6 dimension template files. These templates define the **structured output sections** for each dimension's `.brainstorm/dimensions/<dimension>.md` artifact. The explorer uses template sections as conversation anchors — they define what topics to cover, not blanks to fill.

    Each template should follow this pattern:
    ```markdown
    # [Dimension Name]

    > Template for `.brainstorm/dimensions/<dimension>.md`
    > Explorer uses these sections as conversation anchors during exploration.

    ## [Section 1]

    [Brief guidance on what belongs here — 1-2 sentences]

    ## [Section 2]
    ...

    ---
    *Template: brain-suite/templates/<dimension>.md*
    ```

    **templates/product.md** — Product dimension. Sections:
    - Problem Statement (what pain point, who feels it, how severe)
    - Proposed Solution (core concept, how it addresses the problem)
    - Key Features (prioritized list, MVP vs future)
    - Differentiators (what makes this unique vs alternatives)
    - User Experience Vision (how it should feel to use)
    - Assumptions & Risks (what must be true for this to work)

    **templates/tech.md** — Tech dimension. Sections:
    - Architecture Overview (high-level system design)
    - Tech Stack Choices (languages, frameworks, infrastructure — with rationale)
    - Build vs Buy Decisions (what to build, what to use off-the-shelf)
    - Technical Constraints (performance, scalability, security requirements)
    - Development Approach (MVP strategy, iteration plan)
    - Technical Risks (unknowns, complexity hotspots)

    **templates/market.md** — Market dimension. Sections:
    - Target Market (who, how big, growth trajectory)
    - Market Dynamics (trends, regulatory, timing)
    - Go-to-Market Strategy (channels, positioning, initial traction plan)
    - Pricing Strategy (model, anchoring, willingness to pay)
    - Market Risks (saturation, timing, regulatory)

    **templates/business.md** — Business dimension. Sections:
    - Revenue Model (how money flows in, pricing tiers, unit economics)
    - Cost Structure (fixed vs variable, major cost drivers)
    - Key Metrics (north star metric, leading indicators)
    - Growth Levers (what drives adoption, virality, retention)
    - Business Risks (cash flow, dependencies, single points of failure)

    **templates/competitors.md** — Competitors dimension. Sections:
    - Direct Competitors (who, what they do, strengths/weaknesses)
    - Indirect Competitors & Substitutes (alternative solutions users currently use)
    - Competitive Advantages (your unfair advantage, defensibility)
    - Competitive Risks (who could copy you, how fast)
    - Positioning (how you're different in one sentence)

    **templates/users.md** — Users dimension. Sections:
    - Primary User Persona (who, demographics, psychographics, daily life)
    - User Jobs To Be Done (functional, emotional, social jobs)
    - Current Alternatives (how they solve the problem today, pain points with current solutions)
    - User Journey (discovery → first use → regular use → advocacy)
    - Validation Plan (how to test assumptions about users before building)

    Each template should be 20-40 lines. Section guidance should be specific enough that the explorer knows what to ask about, but brief enough to scan quickly.
